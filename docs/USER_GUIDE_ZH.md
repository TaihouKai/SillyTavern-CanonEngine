# Canon Engine 第一版使用说明

Canon Engine 是一个独立的 SillyTavern 扩展：它记录故事里**实际发生**的历史，并让剧情最终到达作者指定、不可更改的 **HARD 锚点**。你可以随意改变过程，但写明的锚点（内容、结果、时间）一定会发生。

## 一、安装（一次）

1. 把整个 `SillyTavern-CanonEngine` 文件夹放进下面任一位置：
   - `SillyTavern/data/<你的用户名>/extensions/`
   - 或 `SillyTavern/public/scripts/extensions/third-party/`
2. 刷新 SillyTavern 页面。扩展面板里会出现「Canon Engine 历史引擎」。
3. 不需要数据库、后台程序或编译。更新时直接替换文件夹再刷新；你的战役数据保存在聊天文件里，不会因为更新扩展而丢失。

要求：SillyTavern 1.19.0（已测试），使用 Chat Completion 连接（你现有的任何模型都可以），单个 GM 角色的对话。Horae 可选（已测试 1.15.1 Metadata 分支）。

## 二、给一个对话启用（一次）

1. 打开要玩的 GM 对话 → 扩展面板 → Canon Engine →「为此对话启用（导入 .canon.json）」→ 选择历史包文件。
   - 只接受新格式 `.canon.json`。如果选了世界书文件，会直接提示「这是世界书，不是历史包」，不会尝试转换。
2. 预览窗口会显示：标题/版本、校验结果、覆盖时间、HARD 锚点数。
3. 填写**开局时间**（数据时间轴，格式 `D1 09:00`），或选「从某事件之前开始」。可选填写「第 0 天对应的显示日期」，只影响显示，不会用到电脑的真实日期。若 Horae 已记录剧情时间，会一并显示供你参考。
4. 点「确认绑定」。如果是已经玩过的对话，插件会把所有已保存的消息检查一遍（不只是最近几条），**不会重置 Persona、物品、技能或 Horae 状态**。随后显示绑定摘要：开局时间、历史包版本、检查了多少条消息、主要偏离、未解决问题。不满意可以「撤销绑定」。
5. 按提示处理两件事：
   - 停用原来负责「历史事件 / 时间线」的世界书（普通设定世界书可以保留）。插件不会读取或修改它。
   - 如果 GM 卡里有「历史从世界书获取」之类的旧规则，建议手动删掉那一句。插件启用时会注入新的时间线规则覆盖它，但不会改动你的角色卡文件。

## 三、正常玩

- 还是在原来的输入框输入、点发送。
- 输入框上方有一个小状态条：整理对话中 → 规划中 → 生成中 → 检查中 → 保存中 → 就绪。等待期间可以点「取消」（ST 自带的停止按钮也能取消）。
- 回复要等检查通过才会显示完整内容（第一版不逐字流式显示）。故事里不会出现 JSON、标签或规划内容。
- Swipe（左右切换/生成新回复）、重新生成、继续回复都照常使用 ST 自己的按钮，插件会用同样的方式检查每一个候选回复。
- 出现严重偏离时，回复下方会出现红色提示「严重历史偏离……」。它不会剧透未来锚点或幕后计划；删除或切走那条回复，提示也会消失。
- 「检查面板」可以随时查看：当前剧情时间、当前事实及其来源、实际历史、偏离、锚点、计划、恢复状态。未来锚点和计划默认隐藏，勾选「显示剧透」才会显示。面板开关会被记住。

### 插件会帮你记住什么

只要过去发生的事与当前内容**有因果关系，或被直接/间接提到**，插件都会把实际记录交给 GM——不论是你做的、GM/NPC 做的，还是正史在你不在场时发生的，也不论后来是否被逆转。例如：路过早已炸毁的市场，GM 会按废墟描写；有人问起你曾偷走又归还的钥匙，GM 会知道偷窃和归还两件事。GM 的草稿里临时冒出的地点、人物或往事，也会在显示前补查，不符合就让 GM 改写（最多两次）。你不需要手动提醒。

「世界里发生了什么」和「角色知道什么」分开处理：你可以看到废墟而不知道是谁干的；插件不会因此把地点写成完好，也不会把幕后原因告诉你。

## 四、修改、删除、重新生成

- 用户消息和 GM 消息都可以随便改、随便删，包括第一条消息。插件会从最早改动的位置重新整理后续状态；没改动的部分直接复用，不额外调用模型。
- 如果你改了很早的一句话，却保留了与它矛盾的后文（例如把「我救下 Mira」改成「我转身离开」，后面的 GM 回复仍写着救人），插件会：
  - 保留所有文字，在第一条冲突的消息下标出提示；
  - 暂停继续生成；
  - 提供两个选择：「定位此消息」去修改它，或「从此处分支并重新生成」（原对话保留，新分支重新写后续）。
  插件不会自动删除后文，也不会凭空编一个「其实当时……」来圆过去。
- 网络或模型出错、保存失败时，状态条会显示原因和「重试」按钮。你的输入和最后的有效状态都会保留，聊天里不会多出空消息或错误消息。

## 五、备份与更新历史包

- 战役数据就保存在聊天文件里，ST 的普通聊天备份会一并保存。
- 「导出战役备份」会下载一个 JSON（里面有完整历史包和隐藏信息，属于剧透，不要随便分享）；「导入战役备份」可以恢复到当前对话。
- 对话会固定使用启用时的历史包版本。你之后修改了历史包文件，进行中的游戏不会被悄悄改变。要换版本时用「更新历史包…」：先看变化摘要（改动/新增/删除的事件、HARD 合同变化），导出备份后才能应用。

## 六、常见问题

- **为什么回复变慢了？** 每回合除了正文，还要做提取、检查（必要时规划、补算场外事件），一般会多 3～6 次模型调用。
- **能在群聊里用吗？** 第一版不支持，群聊里不会启用。
- **能同时在两个浏览器/设备里玩同一个对话吗？** 不支持。同一浏览器的第二个标签页会被禁止写入。
- **怎么彻底关闭？** 扩展面板里「对此对话停用」，或「解除绑定」删除本对话的引擎数据。
