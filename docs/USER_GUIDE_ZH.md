# Canon Engine 使用说明

Canon Engine 是一个独立的 SillyTavern 扩展：它记录故事里**实际发生**的历史，并让剧情最终到达作者指定、不可更改的 **HARD 锚点**。你可以随意改变过程，但写明的锚点（内容、结果、时间）一定会发生；原作里其他的事件（SOFT / FREE）是“默认历史”，没被你改变就照原样发生，你也可以改变它们。

## 一、安装（一次）

1. 在扩展面板「安装扩展」里填本仓库地址；或把整个 `SillyTavern-CanonEngine` 文件夹放进下面任一位置：
   - `SillyTavern/data/<你的用户名>/extensions/`
   - 或 `SillyTavern/public/scripts/extensions/third-party/`
2. 刷新 SillyTavern 页面。扩展面板里会出现「Canon Engine 历史引擎」。
3. 不需要数据库、后台程序或编译。更新时在扩展管理里点更新（或替换文件夹）再刷新；你的战役数据保存在聊天文件里，不会因为更新扩展而丢失。

要求：SillyTavern 1.19.0（已测试），使用 Chat Completion 连接（你现有的任何模型都可以），单个 GM 角色的对话。Horae 可选（已测试 1.15.1 Metadata 分支）。

## 二、设置面板

面板分成几张卡片，每个选项旁边的 (i) 图标都有简短说明：

- **本对话**：历史包库、启用；启用后有检查面板、重试、重新检查对话、导出备份/导入备份、更换历史包…、暂停引擎/恢复引擎、解除绑定。
- **模型与回复**：分析用连接、回复长度、回复完成时提醒。
- **事件记录**：合并同一场景的本局事件、故事时间跟随 Horae。
- **高级设置**：次数上限、超时、预算、调试模式、界面语言。

## 三、给一个对话启用（一次）

1. **先选「分析用连接」**（见下一节），选好之后才能启用。
2. 打开要玩的 GM 对话，在「历史包库」里点「用此包启用」；或点「为此对话启用（导入 .canon.json）」选择历史包文件。
   - 只接受 `.canon.json` 历史包。如果选了世界书文件，会直接提示「这是世界书，不是历史包」，不会尝试转换。
   - 导入过的历史包会自动存进历史包库（SillyTavern 数据目录 `data/<用户>/user/files/canon-pack-*.json`），以后新对话直接点「用此包启用」即可。点 ✕ 可从库中删除；已绑定的对话各自保存了一份副本，不受影响。
3. 预览窗口会显示：标题/版本、校验结果、覆盖时间、HARD 锚点数。
4. 填写**开局时间**：数据时间轴格式 `D61 17:00`，或按历史包的第 0 天日期填日历时间 `2020-09-18 17:00`，或选「从某事件之前开始」。不会用到电脑的真实日期。若 Horae 已记录剧情时间，会一并显示供你参考。
5. 点「确认绑定」。如果是已经玩过的对话，插件会把所有已保存的消息检查一遍（不只是最近几条），**不会重置 Persona、物品、技能或 Horae 状态**。随后显示绑定摘要；不满意可以「撤销绑定」。
6. 按提示处理两件事：
   - 停用原来负责「历史事件 / 时间线」的世界书（普通设定世界书可以保留）。插件不会读取或修改它。
   - 如果 GM 卡里有「历史从世界书获取」之类的旧规则，建议手动删掉那一句。插件启用时会注入新的时间线规则覆盖它，但不会改动你的角色卡文件。

## 四、分析用连接（必选）

引擎每回合会做几次内部分析（读取你的输入、找出引用、核对回复、规划、补算场外事件），只需要格式严谨，不需要文笔。可以让故事继续用你喜欢的大模型，内部分析改用快速便宜的模型：

1. 在 SillyTavern 里先连接分析用的模型（例如关闭思考的 flash 模型），在“连接配置”（插头图标）中保存为一个配置；
2. 切回你写故事用的连接；
3. 在扩展设置的「分析用连接」选择刚才的配置（也可以明确选择「与当前对话相同」，但用大模型会比较贵）；
4. 如果分析模型是推理模型，在「分析请求的额外参数」里填关闭思考的参数（Venice：`venice_parameters: {disable_thinking: true}`）。SillyTavern 的“包含请求体参数”跟着当前对话的预设走，不会跟着连接配置，所以要填在这里。

GM 的故事回复始终使用当前对话的连接，只有内部分析走这个配置。配置被删除时，回合会停下并提示，而不会偷偷改用故事模型。

## 五、正常玩

- 还是在原来的输入框输入、点发送。
- 输入框上方有一个小状态条：整理对话中 → 规划中 → 生成中 → 检查中 → 保存中 → 就绪。等待期间可以点「取消」（ST 自带的停止按钮也能取消）。回合结束后会显示每一步用了多久、回复字数，以及本回合消耗的 Token（服务商实际返回的用量，包括生成、修改和所有分析请求，不含 Horae 等其他扩展），鼠标移上去可以看详情（包括被退回重发的模型输出、可以忽略的小的自动修正）。
- 回复要等检查通过才会显示完整内容（不逐字流式显示）。故事里不会出现 JSON、标签或规划内容。
- Swipe、重新生成、继续回复都照常使用 ST 自己的按钮，插件会用同样的方式检查每一个候选回复。
- 出现严重偏离时，回复旁边会出现红色提示「严重历史偏离……」。它不会剧透未来锚点或幕后计划；删除或切走那条回复，提示也会消失。
- 「检查面板」可以随时查看：当前剧情时间、当前事实及其来源、实际历史、偏离、锚点、计划、恢复状态。未来锚点和计划默认隐藏，勾选「显示剧透」才会显示。
- **回复长度**（可选）：例如填 `正文约800~1200字`，每次生成和修改回复都会要求这个长度：不到下限不收尾，接近上限时收束当前场景。不会额外请求模型。
- **费用**：状态栏的「消耗 N Token」后面会显示这一回合的实际费用（例如 `· $0.0352`），来自服务商在回复里返回的金额（Venice、unlid 会返回；Venice 用 DIEM 支付时另外显示 DIEM）。悬停可以看到故事模型和分析模型各花了多少；有调用没有返回费用时金额后面带「+」。不包括 Horae、Summaryception 等其他扩展的请求。
- **回复完成时提醒**（默认开）：回合在后台结束时（切到了别的标签页或程序），发一条系统通知，并在标签页标题前加上「✓ 回复完成」（失败时「✗ 回合失败」），回到页面后自动去掉；可选再响一声。浏览器只在 https 或 localhost 下允许系统通知：用局域网 http 地址（例如 `http://192.168.x.x:8000`）打开时只有标题提示和提示音；想要系统通知，可在 Chrome 的 `chrome://flags/#unsafely-treat-insecure-origin-as-secure` 里加入酒馆地址（设置里会显示这两项，各带一个「复制」按钮：网页无法直接打开 chrome:// 页面，复制后粘贴到地址栏即可）。

### 原作事件会怎样发生

- **HARD 锚点**一定会发生（内容、结果、时间不变），只是过程可能不同。规划器会根据实际情况，为接下来两个 HARD 锚点安排路线。
- **SOFT / FREE 事件**没被你改变就照原样发生。事件的时间段开始后，GM 会知道它“正在进行”（前提是它还可能发生）。GM 还会得到一份背景：按原作，接下来 24 小时里其他角色此刻知道什么、想做什么——这只是为了不让角色提前察觉或追查他们本不该知道的事，**不是**必须发生的清单，GM 也不会刻意把剧情往那里引。
- 如果剧情没走到某个 SOFT/FREE 事件，它的时间段结束时会在幕后结算：前提成立、剧情也没碰过相关人物，就按原作发生；剧情已经牵涉到这些人物（或它依赖的事件以不同方式发生了），就由模型按实际经过判断；前提被你破坏了，就记为没有发生。

### 插件会帮你记住什么

只要过去发生的事与当前内容**有因果关系，或被直接/间接提到**，插件都会把实际记录交给 GM——不论是你做的、GM/NPC 做的，还是正史在你不在场时发生的，也不论后来是否被逆转。例如：路过早已炸毁的市场，GM 会按废墟描写；有人问起你曾偷走又归还的钥匙，GM 会知道偷窃和归还两件事。GM 的草稿里临时冒出的地点、人物或往事，也会在显示前补查，不符合就让 GM 改写（最多两次）。你不需要手动提醒。

「世界里发生了什么」和「角色知道什么」分开处理：你可以看到废墟而不知道是谁干的；插件不会因此把地点写成完好，也不会把幕后原因告诉你。

## 六、历史图

点击 SillyTavern 顶栏的流程图图标打开。

- 横轴是真实的时间轴（每个框从事件开始画到结束，很长的空白会被压缩）；分为 HARD / SOFT / FREE / 本局事件四条泳道；红色虚线是当前剧情时间。
- 「本局历史」显示每个原作事件在本局的实际状态（已发生、已改变、未发生、进行中、未来）以及游戏中新产生的事件，箭头是本局实际记录的因果。未来事件默认隐藏，勾选「显示剧透」才显示。
- 「原作历史包」显示历史包本身的事件关系图（含剧透）。
- 可以搜索、按篇章筛选、拖动平移、滚轮缩放、点「全览」；点击事件查看摘要、必须实现的结果、本局实际经过和前后关系。
- **强制完成**（本局历史里点开原作事件，描述下方的红色按钮，需要点两次确认）：把这个事件按原作路线记为已发生，连同它的影响和 HARD 结果；依赖它的后续事件会视为它已发生，下一回合会重新检查计划。「撤销强制完成」可以撤回。
- **即将开始的原作事件**：每次生成回复前，GM 会收到之后 2 小时（故事时间）内开始的原作事件和开始时间。回复写到的时间到了，事件就照常开始：主角在场或会察觉时写出它的开始，否则它在看不见的地方开始、不必提起；GM 不会为了赶上或避开它而加快或拖慢时间。你的消息里明确要求跳过时间时（例如「我睡到明天早上」「三小时后」），范围会延长到跳到的那个时间：期间开始的原作事件都会先告诉 GM，它会写出主角会看到、被吵醒或听说的那些，并保持你要求的跳跃长度。（每条回复结束在什么时间，是写完后才判定的，所以只能提前告知「到了就开始」。）
- **进行中的原作事件**：回复里原作事件刚开始、还没有结果（例如打斗刚开始）时，它会显示为「进行中（结果未定，结束时再判定）」，并列出已发生的部分；进行期间，每一次生成回复时 GM 都会收到这个事件的提醒（已发生的部分和原作路线，原作只作参考），不必在消息里提到它；等它在之后的回复里结束时，才判定为「已发生」或「已改变」。如果故事把它搁置超过窗口结束后一天，才会照常在幕后结算。
- **关联本局事件**（本局历史里点开原作事件）：原作事件其实已经在故事里发生了、但没有被认出来时（例如玩家亲手打倒了原作里由别人打倒的人），点它，勾选对应的本局事件，再选「结果与原作相同（已发生）」——记为已发生并写入原作结果——或「结果不同（已改变）」——以故事里实际发生的为准。本局事件会和原作事件连起来；「撤销关联」可以撤回。不调用模型。
- **重新分析**（本局历史里点开「已发生」或「已改变」的原作事件，需要点两次确认）：按现在的规则重新检查记下这个结果的那条回复——已发生、已改变，还是仍在进行中。之后的回复会像修改过消息一样重新核对；会调用分析模型。开局前的历史和「强制完成」没有可重新分析的回复。
- **整理本局事件**（历史图顶部的按钮）：让分析模型把你的本局事件按情节归成几段，每段显示为一个框，带标题和简短摘要。只影响显示，不改变历史记录、因果关系或 GM 看到的内容；之后新增的事件照常显示，可以随时再点一次；「还原」取消整理。
- **☆ 关注**（尚未发生或正在进行的 SOFT/FREE 事件）：从事件开始前 24 小时到事件结束，GM 会自然地给你的角色机会到场或参与（邀请、传闻、顺路……），但不会强行决定它的经过和结果，你也可以拒绝。事件结算后或时间段过去后，关注会自动取消。
- **合并同一场景的本局事件**（设置里勾选，默认关闭）：同一地点、同一件事里接连发生的小事记成一个框。一个框最多 4 段、90 分钟以内、同一地点；离开建筑、乘车、到了别处或间隔约 30 分钟以上就另起一个；原作事件总是单独一个框。每一段都保留自己的记录，只是归在一起显示。

## 七、故事时间与 Horae

「故事时间跟随 Horae」默认开启：装了 Horae 且它已更新时，每个新回合从 Horae 记录的上一条回复结束时间开始，本回合本身经过的时间由 Canon Engine 估算（正文里写明的时间优先）。Swipe/重新生成/继续时、Horae 还在分析或已过期时、Horae 的时间比引擎早或超前 3 天以上时，不会使用。

## 八、修改、删除、重新生成

- 用户消息和 GM 消息都可以随便改、随便删，包括第一条消息。插件会从最早改动的位置重新整理后续状态；没改动的部分直接复用，不额外调用模型。
- 如果你改了很早的一句话，却保留了与它矛盾的后文（例如把「我救下 Mira」改成「我转身离开」，后面的 GM 回复仍写着救人），插件会：
  - 保留所有文字，在第一条冲突的消息下标出提示；
  - 暂停继续生成；
  - 提供两个选择：「定位此消息」去修改它，或「从此处分支并重新生成」（原对话保留，新分支重新写后续）。
  插件不会自动删除后文，也不会凭空编一个「其实当时……」来圆过去。
- 网络或模型出错、保存失败时，状态条会显示原因和「重试」按钮，「详情」里有可复制的完整报告。你的输入和最后的有效状态都会保留，聊天里不会多出空消息或错误消息。

## 九、备份与更新历史包

- 战役数据就保存在聊天文件里，ST 的普通聊天备份会一并保存。
- 「导出备份」会下载一个 JSON（里面有完整历史包和隐藏信息，属于剧透，不要随便分享）；「导入备份」可以恢复到当前对话。
- 对话会固定使用启用时的历史包版本。要换版本时用「更换历史包…」（或历史包库里的「更新」）：先看变化摘要（改动/新增/删除的事件、HARD 合同变化），导出备份后才能应用。更新后插件会逐条重新核对已保存的消息，只有真正受影响的消息才会再请模型检查。

## 十、常见问题

- **SillyTavern 显示的 token 数为什么这么大？** SillyTavern 的统计会把插进聊天记录里的内容（引擎资料、Horae 快照等）同时算进「聊天记录」和「扩展程序」两栏；而且对它不认识的模型名，它用 OpenAI 的分词器计数，中文会比 Qwen 实际多算约 1.6 倍。以「提示词总 Token 数量」为准，并按这个比例估算。
- **为什么回复变慢了？** 每回合除了正文，还要做读取、检查（必要时规划、补算场外事件），一般会多 3～6 次模型调用。分析用连接选快速便宜的模型会明显加快、省钱。
- **能在群聊里用吗？** 暂不支持，群聊里不会启用。
- **能同时在两个浏览器/设备里玩同一个对话吗？** 不支持。同一浏览器的第二个标签页会被禁止写入。
- **怎么彻底关闭？** 扩展面板里「暂停引擎」，或「解除绑定」删除本对话的引擎数据。
