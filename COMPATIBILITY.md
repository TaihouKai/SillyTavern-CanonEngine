| **Installed Horae** | Fork `TaihouKai/SillyTavern-Horae-Metadata`, manifest **1.15.1**, HEAD `204f5140842d0bf51e3811f6a36706fc487a9211` (2026-10-13). State mode `metadata` (background analysis via aux API, falls back to main API `generateRaw`). Public API used read-only: `getLatestState` (scene, and story date/time for *故事时间跟随 Horae*), `getStateMode`, `isEnabled`, `background.getStatus/isBusy/waitForIdle/reanalyze`, `persona.getRecord` (tests only). In the other direction the fork reads Canon Engine's public clock (`window.CanonEngine.api.getClock`, `canon-engine:clock`) and catches up when Canon Engine is ahead (e.g. a canon time skip). Pre-existing unrelated console error in this fork: `TavernHelper is not defined` at `GENERATION_AFTER_COMMANDS` (harmless; caught by ST's emitter). |
| **Model connection** | ST *Chat Completion*, source `custom` (OpenAI-compatible). Internal tasks use `generateRaw` with a message array; JSON is parsed and validated locally (no provider JSON-schema mode or function calling required); ≤2 attempts with error feedback. Drafts use `generateQuietPrompt` → `Generate('quiet')` = ST's full prompt assembly. No API secrets are read or logged. Internal tasks can go to a separate saved Connection Profile (*分析用连接*) with optional extra request parameters. Live provider: Venice (OpenAI-compatible) through a capped local proxy; all automated suites use a mock server. |
| **Draft isolation** | Native story turns in a bound chat are aborted in the manifest `generate_interceptor` (runs after ST saved the user message, before prompt assembly) and replaced by a managed operation started after the native call unwinds. The draft is a quiet generation: never streamed into the chat. With a custom (OpenAI-compatible) endpoint, Canon's own requests (drafts and analysis calls) go to the provider as streams with `stream_options.include_usage` and are folded back into one ordinary completion before ST sees them, so slow reasoning models do not hit provider gateway timeouts (I09, I14; a provider that refuses the streamed request with a 4xx gets the request as ST built it), no `MESSAGE_RECEIVED` / `CHARACTER_MESSAGE_RENDERED`, never added to `chat`. Only accepted text is published with ST's `saveReply` (native events, swipe metadata). Integration I02: a rejected sentinel draft is absent from chat, Horae metadata, aux analysis, embeddings, the next prompt, the ledger and stored manifests. |
| **Prompt hooks / isolation** | Engine context injected with `setExtensionPrompt(IN_CHAT, depth 1, system)` only during the draft and cleared in `finally`. Internal task requests: Horae's own `[HORAE_INTERNAL:NO_CONTEXT_INJECTION]`/`NO_VECTOR_RECALL` markers + a last `CHAT_COMPLETION_PROMPT_READY` listener restores the exact 2 task messages (verified: no card/persona/AN/lore/Horae text reaches tasks). Dry runs are ignored. |
| **Native operations** | Send: interceptor + managed op. **Regenerate:** ST deletes the old reply *before* interceptors run, so it is captured at `GENERATION_STARTED` (first listener) and restored if the op fails or is cancelled. **Swipe:** after an aborted overswipe ST's `endSwipe` reverts its own slot, so the managed op waits for the swipe state to settle and opens the native slot itself before `saveReply({type:'swipe'})`; the replaced reply is removed from the candidate prompt in the interceptor (prompt copy only — the shared `chat` array is never mutated while awaiting). **Continue:** private continuation instruction, whole revised message validated, published with `saveReply({type:'appendFinal'})`. **Edit/delete/swipe-select:** `MESSAGE_EDITED/DELETED/SWIPED/SWIPE_DELETED/UPDATED` trigger a debounced reconcile and fail in-flight fences; manifest comparison is the safety net (verified with an external in-memory edit). **Branch:** ST creates a new chat file with copied metadata and a fresh `integrity` slug → new `branchId`. **Rename:** same integrity → identity kept. **Reload:** ST on this install shows the welcome screen; after the chat is reopened the replay is deterministic (0 model calls). |
| **Persistence** | `chat_metadata.canonEngine` + `message.extra.canonEngine`. Saves go through ST's serialized `saveChatConditional` (direct concurrent `saveChat` calls raced with ST/Horae saves and failed on Windows with `EPERM` during ST's atomic rename — observed and fixed) and are **verified** by reading the chat file back (`/api/chats/get`, save token). Commit journal written before publication; publication + journal persist atomically in one chat file; recovery finalizes or discards it. Backup export/import round trip tested. |
| **Memory repair** | Before each managed draft: wait (bounded) for Horae background analysis; detect messages whose Horae status is `outdated`/`failed`; call Horae's supported `background.reanalyze(i)` once and re-check. If still stale/busy, Horae's injected snapshot is removed from that request's final prompt (`CHAT_COMPLETION_PROMPT_READY` diff) and a notice is shown. Verified in the actual outgoing prompt (I04 exclusion + repair paths). Horae summaries/vectors are never used as engine evidence. |
| **Group handling** | Not supported. `bind` refuses group chats with an explicit message; the interceptor never acts in a chat without a binding; no enforcement is claimed. |
| **Concurrency** | One active writer per campaign per browser profile (localStorage heartbeat); a second tab cannot generate. Independent browsers/devices writing the same chat are unsupported; ST's server-side chat integrity check is the only cross-device guard. |

## Version sensitivity

The adapter depends on: `generate_interceptor` semantics, `Generate('quiet')`, `saveReply` types (`normal`/`swipe`/`appendFinal`), `swipe.state()`, `saveChatConditional`, `/api/chats/get`, `setExtensionPrompt`, the event names above, and the ordering facts recorded in the table (regenerate deletes before interceptors; aborted overswipe reverts the slot). All are isolated in `src/adapters/st.ts` and `src/index.ts`; re-run `tests/e2e/integration.mjs` after an ST update.
